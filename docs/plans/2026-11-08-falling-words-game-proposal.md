# 网页落字游戏方案

日期：2026-11-08  
更新：2026-11-09  
状态：首版已在开发分支实现，等待试玩评审；原生系统输入法候选窗仍待人工验收。

已确认：完整输入一个字或词后自动发射一颗子弹，消除整个目标。

已确认的视觉方向：沿用当前字感样式，子弹表现为一小段带光晕的光标。

## 体验与范围

网页版增加「练习 / 游戏」模式切换。游戏采用生存规则：文字从不同横向位置陆续落下，玩家在底部输入区输入任意一个目标的完整文字，系统自动瞄准并发射。目标触底扣除一条生命；生命归零后结算。

第一版建议以简体中文单字和双字词验证手感。规则和词库结构预留英文及粤语；三种语言的词库和难度需要各自准备。界面继续使用网页版现有中英文和明暗主题。

游戏界面沿用字感现有的字体、留白、文字层级、主题和强调色。顶部显示得分、生命、等级及暂停按钮。中间为占据主要空间的下落区域。底部先是底线，再是发射点和真实输入框。文字在逻辑上分列出生，但不显示网格线。玩家只负责输入，发射点自动朝向匹配目标。

```text
字感        练习 | 游戏                     暂停

得分 120             生命 5             等级 1

         雨                          山

                        春天

              阅读

────────────────────────────────────────── 底线
                       |
                   [ 输入文字 ]
```

准备界面提供开始按钮和一条规则说明。点击开始后先聚焦输入框，再倒数进入游戏。结算显示得分、存活时间、消除数量、最高连击及重新开始按钮。

## 开发分支与合并流程

本地开发分支为 `codex/falling-words-game`，从 `main` 的 `0ee6f52` 创建。使用当前工作区，不额外创建工作树。现有方案文档随工作区保留。

游戏在该分支完成实现、构建、测试和浏览器试玩。提供可检查的差异与试玩结果后，等待用户明确确认合并，再将分支合入 `main`。合并前不更新 `main`；推送开发分支、部署预览和正式发布需要按对应任务的授权范围执行，不将这些动作混为合并。

分支隔离整个仓库的改动；游戏入口只接入网页版。游戏逻辑仍放在 `packages/practice/src`。若抽取共用输入处理，需要验证原有网页和 DSH 插件的输入、快捷键与记录。

## 沿用现有光标的视觉表现

- 子弹使用独立的 DOM 元素，沿用当前竖线光标的约 3px 线宽、圆角、强调色和光晕阴影。飞行时沿目标方向移动并旋转，不需要新的图片资产或游戏引擎。
- 底部发射点同样用光标形态表现，与页面文字保持一致的视觉尺度。
- 目标使用现有字体和正文颜色；前缀匹配时用强调色突出已匹配部分；命中时短暂提亮并淡出。
- 触底使用现有错误色作局部反馈，生命数量同步减少。
- 飞行子弹与真实输入框的光标是两个对象。发射动画不移动输入框，不影响输入焦点和原生候选窗。
- 复用明暗主题，并遵循系统的减少动态效果偏好；装饰动画不改变命中、扣血和计分结果。

## 规则建议

以下数值是首轮调试参数，尚未经过试玩验证。

| 项目 | 建议初始规则 |
| --- | --- |
| 生命 | 5 条；漏掉一个目标扣 1 条；生命归零结束 |
| 初始落地时间 | 单字从完整出现到触底约 9 秒；双字词稍慢 |
| 出生间隔 | 起始约 2.4 秒一个目标 |
| 同屏数量 | 起始上限 5 个；没有合适的出生位置就延后出生 |
| 难度递增 | 每存活 30 秒提升一级；逐步缩短出生间隔及落地时间，两者都设下限 |
| 积分 | 消除目标获得 10 × 字数；首版连击用于反馈及结算 |
| 错字 | 不发射、不扣生命；输入框反馈错误，玩家用退格修改；连击归零 |
| 漏字 | 目标消失、扣生命、连击归零；每个目标只结算一次 |
| 暂停 | 暂停出生、下落、子弹和游戏计时；显式点击继续后恢复 |

长词需要更多输入时间，应给目标独立的落地时间系数。先用单字、双字词验证，再加入三字、四字词。不能把中文字数、拼音按键数和实际输入耗时视为同一个指标。

布局缩小时，根据真实可用宽度减少逻辑列数和同屏上限。下落进度使用 0–1 的相对值，改变窗口尺寸不应使目标突然触底。移动端需要在软键盘展开后的可见区域内放置底线和输入框。

## 输入与目标匹配

输入过程分成「输入法正在组字」和「文字已确认上屏」。只有已确认的文本可以参与攻击。空格、数字、回车和 Escape 在组字期间继续由输入法处理。

例：屏幕存在「春天」。玩家输入拼音 `chuntian` 时，文字继续下落，系统不攻击。玩家选中「春天」后，系统读取真实输入框中的确认文本，匹配成功，发射一颗子弹，清空本次已消费的输入并保留焦点。

玩家也可以先上屏「春」，再上屏「天」。「春」保留为已确认前缀；两次输入合并成「春天」后发射。英文将使用同一个已确认缓冲区，逐字输入完整单词后发射。

匹配规则：

1. 输入内容与一个可攻击目标完全一致：预订该目标并发射，消费对应输入。
2. 输入内容只是目标的前缀：保留输入，突出显示可匹配目标，等待继续输入。
3. 输入内容不是任何目标的前缀：保留文字并显示错误，等待玩家修改。尚未完成的前缀不算错字。
4. 一次提交包含多个目标的完整文字：按先后顺序消费，例如「春天山」可依次攻击「春天」和「山」。其余未消费的文字留在缓冲区。每个目标最多被预订一次。
5. 对应目标在输入完成前已经触底：先结算触底，该目标不再匹配。原有输入保留，允许玩家修改；不因目标过期清空正在组字的输入框。

出生时禁止仍在场的目标出现重复文字，也禁止完整前缀关系。例如「天」与「天空」不同时出现；「天空」与「天气」可以同时出现，玩家上屏「天」时，两者都属于候选。出生检查还需要考虑当前已确认的输入前缀，避免新增目标让正在进行的匹配变得含糊。

这些限制消除了自动发射时的歧义，也省去了鼠标选目标和额外确认键。词库暂时找不到合适目标时，延后出生，不放宽约束。

粘贴和拖入文本沿用当前练习的处理方式，不作为游戏攻击输入。

### 原生输入保护

现有练习已经根据真实文本框缓冲区处理组字结束及后续 input 事件，而不是直接重复追加 event.data。游戏需要复用这一原则，但游戏会在命中后消费并清空缓冲区，因此需要额外维护本次提交的消费状态：同一次提交只处理一次；下一次输入相同词语仍是新的提交。

只抽取确实共用的输入处理，不复制现有练习组件。练习的全文判分与游戏的目标匹配分别保留。游戏结束、重开或切换模式后，旧输入元素的迟到事件不应再修改新一局状态。

真实输入框固定在底部，让原生输入法候选窗跟随输入框光标。目标文字、发射点和子弹均不接管输入焦点。组字期间不重建输入框，不主动改写输入框的值。

## 发射与触底的先后关系

推荐以「完整文字确认上屏的时刻」判断攻击是否来得及。

- 完成时刻早于目标触底时刻：立即将目标设为已预订，记分并排除触底判定。随后用约 100–180 毫秒的子弹动画表现命中。
- 完成时刻等于或晚于目标触底时刻：目标已经漏掉，扣除生命，不再发射。

这样玩家在底线前输入成功就一定能消除目标。子弹飞行距离不会改变判分。命中的目标可以在当前位置短暂停留并淡出，使画面和判定一致。

另一种方案是计算子弹飞行与移动目标的真实碰撞，但它会把飞行距离也变成失败因素，需要另行解释、调速和验收；首版不建议采用。

目标状态只能单向变化：

```text
下落中 ──匹配成功──> 已预订 ──命中动画完成──> 已消除
   └────触底──────> 已漏掉
```

已预订的目标不再接收攻击，也不会扣生命。重开时清理动画并更新局 ID，防止上一局的动画回调影响新一局。

## 时钟、暂停与结束

游戏具有「准备、倒数、进行、暂停、结算」五个状态。开始进入倒数，倒数结束后启动出生和下落。生命归零立即停止游戏并生成一次结果。重开创建一局新的状态。

引擎维护排除暂停时长的游戏时钟。动画帧和输入提交使用同一条时间线。收到输入时，先推进到该次输入的处理时刻并结算此前已经触底的目标，再进行匹配，避免先输入还是先刷新画面影响结果。

位置根据累计有效时间计算，不使用「每帧加固定像素」。浏览器切到后台或游戏输入失去焦点时自动暂停。返回页面后等待玩家点击继续。继续时重置动画帧基准，避免一次跳过很长时间。窗口尺寸变化期间，必要时也先暂停再重排。

组字期间按 Escape 继续由输入法处理；非组字期间建议沿用网站现有 Escape 重开语义。暂停使用界面按钮，不增加其他全局快捷键。若游戏在组字中结束，冻结游戏判分，允许原生组字收尾；结算后到达的提交不再攻击目标。

## 技术方案与项目接入

| 方案 | 适用性与代价 |
| --- | --- |
| DOM 文字 + CSS 光标子弹，推荐 | 目标数量少，容易沿用现有字体、主题、光标光晕和真实文本框；首版无需引入游戏引擎 |
| Canvas 场景 + DOM 输入框 | 更适合大量粒子和密集目标；文字排版、缩放和可访问性需要单独处理 |
| 专门的游戏引擎 | 适合复杂关卡和物理系统；当前玩法需要的能力有限，会增加依赖和接入工作 |

建议拆分为独立可测试的游戏引擎及 React 场景。引擎接收时间、输入和随机数，输出目标、积分、生命及事件。视图负责绘制，不在动画回调中分别维护另一套判分状态。动画层更新目标位置；React 更新出生、命中、生命和模式等离散变化，避免每帧重建整个页面。

首版文件划分如下：

```text
packages/practice/src/
  native-input.js          共用的确认文本与提交去重处理
  cursor-style.js          共用光标光晕
  game/
    engine.js              时钟、出生、匹配、下落、生命、结算
    records.js             独立游戏记录
    create-game.js         React 游戏场景与真实输入框
    styles.js              游戏样式，使用现有主题变量
data/
  game-words.json          人工检查过的游戏字词表
apps/web/src/
  main.js                 网页模式切换与按需加载
```

游戏行为放在权威共享源码 `packages/practice/src`。网页负责游戏入口，DSH 插件继续使用现有入口。网页不导入插件模块或本地对话接口。

现有语料是文章库，没有经过游戏验证的独立词表。建议新增独立字词表，记录稳定 ID、语言、文字和难度。单字检查可辨认性，词语检查完整性；不在运行时把文章随意切片后直接作为目标。后续注音可复用现有引擎，先不增加第一版的匹配复杂度。

游戏记录使用新的浏览器存储键，例如 `typefeel.game.records.v1`。记录规则版本、词库版本、语言、难度、得分、存活时间和最高连击。存储失败时仍可继续游戏，并提示记录未保存。游戏分数与普通练习的速度、准确率分开统计。

## 实现顺序与验收

1. 建立纯逻辑引擎和受检查的字词表，用固定时钟与随机序列验证出生、匹配、触底和结算。
2. 接入真实中文输入，验证整词上屏、分次上屏、取消组字、重复事件、连续输入相同文字和退格修改。
3. 接入场景、自动瞄准、子弹和消除反馈，验证画面与判分一致。
4. 接入网页模式切换、主题、暂停、结果和本地记录，再调节难度。

关键验收：

- 「春天」在底线前确认上屏，只发射一颗子弹、计一次分、不扣生命。
- 子弹动画尚未结束时，目标不会重复扣血或接收另一发攻击。
- 目标触底只扣一条生命；同一时刻多个目标触底按目标数量结算，生命不低于零。
- 已确认前缀不是错字；中文组字过程和候选选择不触发攻击。
- compositionend 与 input 重复通知不重复发射；下一次相同词语可以正常攻击。
- 前缀关系不会造成单字提前抢走词语输入；一次确认多个目标的消费顺序固定。
- 切后台、暂停和继续不会跳帧扣血；低帧率不会改变下落速度。
- 重开、模式切换和结算后，旧输入与动画事件不会修改当前局。
- 桌面及窄屏都能看到目标、底线和输入框；软键盘展开后输入区仍可使用。
- 系统中文输入法的候选窗必须通过真实手工输入验证；模拟事件测试不足以证明候选窗位置正常。
- 最终实现后运行 `npm run build`、`npm test`，并回归现有网页及插件的输入、快捷键和记录。

首版已实现上述主要流程，使用 120 个中文单字及双字词。构建、规则测试、浏览器组字事件和响应式布局的证据见 [试玩验证记录](../verification/2026-11-09-falling-words.md)。下落节奏仍需用户试玩调节；原生系统输入法候选窗须在合并验收前补充人工确认。
